# x-a11y: cross-cutting static accessibility audit

Auditor: agent-161 (QA swarm, cross-cutting lane)
Scope: `web/index.html` + `web/feat/*.js` (85 web files, no page owned)
Method: static only (`ops_grep`, `ops_inspect_local_file`, curl against `http://127.0.0.1:8798`). No browser tools, per contract.
Date: 2026-11-22

## Verdict

No critical findings. One important keyboard-focus gap in the popovers. Everything else is
minor ARIA polish. All text contrast passes WCAG AA; one documented ratio in
`polish-contrast.js` does not match a re-measurement (both values pass).

## Files audited

Cross-cutting: `web/index.html` (3504 lines) and all 84 `web/feat/*.js` files, plus
`web/plugins.js`. Standalone pages (`admin.html`, `auth.html`, `landing.html`, `legal.html`,
`reset.html`) were only checked for the favicon reference.

## Findings

| # | Severity | Where | What | Evidence | Fix |
|---|---|---|---|---|---|
| 1 | important | `web/index.html:1232-1239` | `openPop()` positions and animates `bellpop`/`acctpop` but never moves keyboard focus into them. A keyboard user who opens the account or notifications menu with Enter has focus left on the trigger while the popup is visually open; Esc (`index.html:1266`) closes it, but the menu items were never reachable without a Tab from an unknown position. | `openPop` body only calls `style` assignments, `pop.classList.add("open")` and `animate`; no `focus()` call. `aria-expanded` is managed (`index.html:1231`, `1360-1362`), so the state is announced but focus never enters. | After building `innerHTML` in `openBell`/`openAcct`, focus the first focusable child (or `pop.querySelector("button")?.focus()`); return focus to the trigger on close. `web/feat/polish-keyboard.js:148-169` already does exactly this pattern for the keyboard panel. |
| 2 | minor | `web/index.html:920`, `1261-1262` | `acctpop` has `role="menu"` but its child buttons (Settings, AI usage, Tour, Send feedback, Sign out) have no `role="menuitem"`, so screen readers get a menu with no menu items (ARIA 1.2 required owned elements). | `<div class="pop" id="acctpop" role="menu">` at 920; children are plain `<button data-act=...>` at 1261-1262. | Add `role="menuitem"` to the five buttons, or drop `role="menu"` from the container. |
| 3 | minor | `web/feat/brand-ai.js:29,36`; `web/feat/meme-timeline.js:95`; `web/feat/pictures.js:175` | Three text inputs have placeholder-only accessible names (no `<label>`, no `aria-label`). Browsers fall back to the placeholder so they are announced, but the name disappears once the user types, which is a WCAG 3.3.2 smell. | `brand-ai.js:29` and `:36` `<input data-bai-q placeholder="Ask about your numbers">` in both card branches; `meme-timeline.js:95` `<input data-wq placeholder="Search sounds">`; `pictures.js:175` `<input id="pics_tname" placeholder="Name this layout">`. | Add `aria-label` as the other 20+ search inputs already do (`analytics-table.js:179`, `nav-search.js:58`). |
| 4 | minor | `web/index.html:906` | `<div class="scrim" data-act="menu">` is a clickable div: no `role`, no `tabindex`, no accessible name. Mouse users can close the mobile sidebar with it; keyboard users cannot reach it at all (they must use Esc). | `<div class="scrim" data-act="menu"></div>` with `data-act` delegation in `web/plugins.js:152`. | Make it `<button class="scrim" data-act="menu" aria-label="Close menu">` or add `role="button" tabindex="0"`; restyling unchanged. |
| 5 | minor | `web/feat/analytics.js:112-122`; `web/index.html:2743-2782` | Both tab sets stop short of the ARIA tabs pattern: tabs have `role="tab"` + `aria-selected` but no `aria-controls`, panels have no ids and (in analytics) no `role="tabpanel"`/`aria-labelledby`; no arrow-key navigation (Esc only). Controls remain clickable and keyboard-reachable, so nothing is broken. | `analytics.js:112` `role="tablist" aria-label="Analytics views"`, `:113` tab buttons, `:122` panels in `data-an-panels`; `index.html:2743-2753` clip-editor railnav with `role="tabpanel" hidden` panes. | Give each tab an `aria-controls` id and each panel `role="tabpanel"` + `aria-labelledby`; optional: arrow-key nav as in `polish-keyboard.js` GROUPS. |
| 6 | minor | `web/feat/polish-contrast.js:29,37`; `web/index.html:715` | Documented ratios drifted from re-measurement. Header claims `--faint #A0948C on --bg #0A0A0A = 7.24`; recomputed WCAG luminance gives 6.70 (both pass 4.5, no user impact). Header also claims `.bell .dotn` was switched to dark ink at 5.9:1, but the CSS still says `color:#fff`; white on `#C81E28` measures 5.72:1, which passes 4.5, so again no user-facing failure, but the file asks people to trust its numbers. | `polish-contrast.js` header lines vs computed values: #F5F5F5/#0A0A0A = 18.16 (matches), #7C7C7C/#0A0A0A = 4.75 (header 4.79, matches within rounding), #A0948C/#0A0A0A = 6.70 (header 7.24, drift); `index.html:715` `background:#C81E28;color:#fff`. | Re-measure and update the header numbers; either land the dark-ink `.dotn` fix or delete the claim. |
| 7 | minor | `web/feat/polish-keyboard.js:142` | The `.pckb-panel` is appended to `document.body`, outside the `#main, dialog` scope that `polish-contrast.js:29` uses to set `--faint`, so its `.pckb-gh`/`.pckb-note` greys fall back to the root `#7C7C7C` = 4.75:1 (passes 4.5, but inconsistent with the app-wide 6.70 and 0.05 above the .hint failure margin the palette fixed). | `panel.style` / `document.body.appendChild` at 142; scope selector `#main, dialog` in `polish-contrast.js:29`. | Extend the contrast scope to include `.pckb-panel`, or set `--faint` explicitly on the panel. |

## Checks run

1. **Inputs without labels** - all 150 `<input|<textarea|<select` matches read with context across `web/index.html` + `web/feat/*.js`. 147 labelled (wrapped `<label>`, `<label for>`, or `aria-label`); 3 placeholder-only -> finding 3. Hidden file inputs (`index.html:917,98`) fine.
2. **Images without alt** - all 107 `<img|tabindex|role=` matches read. Every `<img` carries `alt=""` (decorative) or real text (`live-heading.js:71`, `index.html:901,2414,3452`); SVG `role="img"` nodes carry `aria-label` (`analytics-charts.js:135`, `usage.js:182`, `learn-signals.js:89`, `index.html:2099,2604`). No finding.
3. **tabindex misuse** - `tabindex="[1-9]"` = 0 hits; only `tabindex="0"` (`analytics-retention.js:181`, `log.js:32`, `schedule.js:89`) plus dynamic set/remove in `polish-mobile.js:106-119`. No finding.
4. **Div/span buttons** - all 7 non-button elements with `data-act` read: 6 fine (`<a href>` links, keyboard-activatable radio `index.html:2021`); 1 clickable div -> finding 4. `onclick=` only in `igcaption.js:78` (delegated to closest button; fine).
5. **Dialog / popup focus + ARIA** - native `<dialog>` (`clipdlg` `index.html:915`/`2719`, `formdlg` `916`, confirms `1019,1324,1979,3252`) gets native focus containment; `tr-card` (`1049`) carries `role="dialog" aria-modal="true" aria-labelledby="trT"`; `polish-keyboard.js` panel is the model citizen (focus in/out, Esc, focus-visible). Popovers -> finding 1; `role="menu"` -> finding 2. `bellpop` has loading/empty/error states (`index.html:1243-1252`).
6. **Contrast** - `polish-contrast.js` read fully; WCAG ratios recomputed from hex (18.16, 4.75, 6.70, 5.72). All text passes 4.5:1 -> findings 6-7 are documentation/consistency only. No text below 3:1.
7. **390px viewport overflow** - every fixed-width node traced to a scroll container or cap: `.ant-t min-width:960px` inside `.scroll{overflow-x:auto}` (`analytics-table.js:18,156`, `index.html:619`); `.aa-map min-width:520px` inside `.aa-scroll` (`analytics-audience.js:25`); `.dlg 450px max-width:100%` (`index.html:645`); `.tr-card 400px max-width:calc(100vw - 24px)` (`index.html:842`); `.pics-canvas 405px max-width:100%` (`pictures.js:48`); `.scroll table:not(.stack) min-width:560px` (`index.html:883`). No finding. Breakpoints exist at 900/760/700/680/640/620/560/430px.
8. **Routes** - curl: 18 sampled `/app/<page>` routes all 200 (`/app/analytics|settings|library|review|schedule|day|learn|help|usage|audio|creators|autofocus|pictures|brand|backup|logfare|knowledge`), `/` = 303 (sign-in redirect, normal), `/brand/logo-light.svg` + `/brand/favicon.svg` = 200 (every page's favicon link resolves). 20 sampled API GETs: 18x 200, 2x 400 (`/api/analytics/retention`, `/api/stats/video` require params - route exists, expected without args). No 404/500 on any referenced route; suspicious `/api/clips` + `/api/videos` captures were truncation artifacts of `/api/clips.zip` (`studio/server.py:1134`) and `/api/analytics/videos`.
9. **Dead controls / console risk** - click delegation single path `e.target.closest("[data-act]")` (`web/plugins.js:152`); `P.page` render failures surface as toast + `console.warn` (`plugins.js:132-136`); `keys.js:52` ignores shortcuts inside buttons/links. `console.warn|error|log` only; no other console calls. 357 `catch` occurrences across the app (healthy error coverage).
10. **States** - loading/empty/error spot checks: `analytics-table.js` (`LOADING` :67, `.ant-empty` :34, `.ant-err` :36 with retry button), library/review/creators empty states with guidance copy (`index.html:1992,2078,2134,2191,2197`), `bellpop` all three states. Toasts: `<div id="toasts" role="status" aria-live="polite">` (`index.html:918`).
