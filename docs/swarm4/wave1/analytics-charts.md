# analytics-charts

**What I built.** Two charts in `#an_charts`, drawn as inline SVG with no library. The first is Views per day across the chosen range; the second is Watch time per day in the same shape. Each chart has a title, the unit above the y axis, three gridlines with labels, at most six dates along the bottom, and a legend that names both lines. The main line is `currentColor` at 2.2 px with a faint fill under it. The comparison period is a thinner dashed line, so it reads as background against this range. Hovering or tapping a day moves a dashed cursor to that day and fills one absolutely positioned box with the date and both numbers; a day with no comparison number shows a dash rather than a zero. All the hover text sits in a normal div, never a `title` attribute, so it appears at once and can be read on a touch screen.

A range with no numbers gets a sentence. Views says "No views in this range yet" and watch time says "No watch time in this range yet", both inside a card that still names the chart and the dates, with no empty axis drawn. If one metric fails the other chart still draws, because each is fetched and handled on its own; the failed one shows "The numbers could not be read. <reason>. Reload this page to try again." Before the first answer arrives the box says "Reading views and watch time for <range>." The unit shown comes from the route when the route sends one, so watch time reads `minutes` when YouTube is connected and `clips` when it is not, instead of promising a unit the data does not carry.

**What I could not do.** `#an_charts` is not created by any current file. The Analytics shell that owns the tab strip is another agent's work, and the box was not mine to create, so the file finds nothing to paint until that shell draws it. It watches `#view` and fills the box whenever the box appears, which is how the two analytics files beside mine do it. Two further limits. The brief said to ask for `metric=estimatedMinutesWatched`, but the live route rejects that name with HTTP 400 and answers with the names it does accept, one of which is `watch_time`. So the file asks for `estimatedMinutesWatched` first and falls back to `watch_time` on refusal. That fallback is load bearing today, not a precaution. And the route reads only `days`, ignoring `start`, `end` and the comparison dates. It never sends a comparison series, so until wave 2 agent 3 builds the full route the dashed line and the second legend entry do not appear, because drawing them from nothing would be a lie. The file already accepts a comparison list beside the points, under several spellings, and lines it up by position rather than by date, since a previous period is a different set of dates. I proved the comparison path with a stubbed route rather than a real one.
